[[general]]
== Geral

Existem várias perguntas e respostas gerais.

.Qual a diferença entre ONTAP Select Deploy e ONTAP Select?
ONTAP Select Deploy é o utilitário usado para criar clusters ONTAP Select. Atualmente, ONTAP Select Deploy é o único método disponível para criar um cluster de produção. ONTAP Select Deploy também pode ser usado para criar um cluster Select de avaliação, permitindo que os clientes testem e documentem as etapas reais de uma implantação em produção. ONTAP Select Deploy também pode converter um cluster de avaliação em um cluster de produção usando uma licença Capacity Tier apropriada, com capacidade suficiente para cobrir o espaço consumido durante a avaliação.

ONTAP Select Deploy é uma máquina virtual que contém uma imagem do ONTAP Select. Durante a instalação do cluster, ONTAP Select Deploy realiza diversas verificações para ajudar a garantir que os requisitos mínimos do ONTAP Select sejam atendidos. A máquina virtual ONTAP Select Deploy e os clusters Select podem ser atualizados separadamente.

.Como posso solucionar um problema de desempenho com ONTAP Select?
Assim como ONTAP em FAS, os dados de desempenho devem ser coletados usando o utilitário perfstat. Aqui está um exemplo de comando:

[listing]
----
perfstat8 –i N,m -t <sample time in minutes> --verbose --nodes=<filer IP> --diag-passwd=abcxyz --mode="cluster-mode" > <name of output file>
----
.Como faço para acessar a página da API Swagger para ONTAP Select Deploy?
[listing]
----
http://<Deploy-IP-Address/api/ui
----

NOTE: A versão 3 da API não é compatível com versões anteriores da API. Um novo procedimento de API está disponível em  https://library.netapp.com/ecm/ecm_download_file/ECMLP2845694["Field Portal"^].

.É possível fazer backup da máquina virtual ONTAP Select com snapshots da VMware ou de outros terceiros?
Não. A máquina virtual ONTAP Select usa unidades independentes e persistentes, que são excluídas dos snapshots baseados em VMware. O único método compatível para fazer backup do ONTAP Select é o SnapMirror ou o SnapVault.

.Onde posso obter esclarecimentos para perguntas que não foram abordadas nesta FAQ?
Contato link:mailto:ng-ses-ontap-select@netapp.com["ng-ses-ontap-select@netapp.com"].



[[licenses-installation-upgrades-and-reverts]]
== Licenças, instalação, atualizações e reversões

Existem diversas perguntas e respostas relacionadas a licenças, instalação, atualizações e reversões.

.É possível atualizar o ONTAP Select e o ONTAP Select Deploy separadamente?
Sim. O utilitário ONTAP Select Deploy pode ser atualizado separadamente do cluster ONTAP Select. Da mesma forma, o cluster Select pode ser atualizado separadamente do utilitário ONTAP Select Deploy.

.É possível atualizar o ONTAP Select usando o mesmo procedimento de um cluster FAS?
Sim, o procedimento de atualização para um cluster Select é idêntico ao de um cluster FAS, embora o binário de atualização do ONTAP Select seja um download separado do binário de atualização do ONTAP on FAS.

.O ONTAP Select pode ser revertido usando o mesmo procedimento de um cluster FAS?
Sim, o procedimento de reversão para um cluster ONTAP Select é quase idêntico ao procedimento de reversão para um cluster FAS. Existem algumas diferenças, no entanto:

* Somente instâncias atualizadas do ONTAP Select podem ser revertidas, e apenas até a versão de instalação original. Novas instalações não podem ser revertidas para uma versão de código anterior, mesmo que ONTAP Select em geral seja compatível com essa versão anterior.
* Para ONTAP Select (KVM) e ONTAP Select (ESXi) que utilizam RAID por software, não é possível reverter para uma versão anterior que não suporte RAID por software. Além disso, uma nova instalação do ONTAP Select 9.5 ou posterior no ESXi usa os drivers de rede VMXNET3 e, quando possível, o driver vNVMe. Não é possível reverter essas novas instalações para versões anteriores do ONTAP Select.
* Se a ONTAP Select VM também foi atualizada para uma instância Large (usando a licença Premium XL), a reversão para uma versão anterior à 9.6 não é compatível, pois o recurso de instância Large não está disponível em versões anteriores.


.O ONTAP MetroCluster SDS exige, no mínimo, uma licença Premium?
Sim.

.É possível alterar a configuração de rede do cluster ONTAP Select após a instalação?
As alterações nas seguintes propriedades do cluster ONTAP Select são reconhecidas pelo ONTAP Select Deploy usando a operação de atualização do cluster disponível por meio da interface do usuário, CLI ou API REST:

* Configuração de rede (endereços IP, DNS, NTP, máscara de rede e gateway)
* ONTAP Select cluster, nome do nó e versão


As seguintes alterações de máquina virtual do ONTAP Select também são reconhecidas:

* Alterações de nome e estado da VM ONTAP Select (por exemplo, online ou offline)
* Alterações no nome da rede do host e no nome do pool de storage


A atualização para ONTAP Select Deploy 2.6 habilita o suporte a essas alterações para qualquer cluster ONTAP Select que já esteja implantado, mas que não tenha sido alterado em relação à sua configuração original. Em outras palavras, se as propriedades do cluster ONTAP Select mencionadas acima foram alteradas usando System Manager ou vCenter, então a atualização para ONTAP Select Deploy 2.6 não corrigirá essas inconsistências. As alterações nas propriedades do ONTAP Select devem ser revertidas primeiro para que o ONTAP Select Deploy adicione seus metadados exclusivos a cada máquina virtual ONTAP Select.

.É possível alterar a configuração de rede do ONTAP Select Deploy após a instalação?
Não há suporte para modificar os detalhes de rede da instância do Deploy após ela estar em execução em um ambiente. Para obter mais informações, consulte o artigo da Knowledge Base link:https://kb.netapp.com/onprem/ontap/ONTAP_Select/Modifying_DNS_configuration_of_ONTAP_Deploy_instance["Modificando a configuração de DNS da instância do ONTAP Deploy"^].

.Como o Deploy detecta que as licenças do ONTAP Select foram renovadas?
O método é o mesmo para todas as licenças, embora os detalhes variem dependendo se é uma licença de Capacity Tier ou de Capacity Pool.

* ONTAP Select Deploy detecta se as licenças e os contratos de suporte são renovados com a compra de um arquivo de licença atualizado da NetApp. O arquivo de licença (.NLF) inclui capacidade, datas de início e término; e é gerado no link:https://mysupport.netapp.com/site/["Site de suporte da NetApp"^], e então atualizado no servidor Deploy.
+

NOTE: Você pode carregar o NLF no servidor de Deploy usando as funções *Add* e *Update*. *Add* adiciona novas licenças ao servidor, e *Update* atualiza os arquivos existentes com informações como capacidade, licença de nó (standard, premium, premium XL), datas de início e término do suporte (Capacity Tier license) ou datas de início e término da assinatura (Capacity Pool license).

+

CAUTION: Não tente modificar o arquivo de licença. Fazer isso invalida a chave de segurança e torna a licença inválida.

* Uma *licença Capacity Tier* é uma licença permanente por nó, vinculada ao número de série do nó ONTAP Select. Ela é vendida com um contrato de suporte separado. Embora a licença seja permanente, o contrato de suporte deve ser renovado para acessar upgrades do ONTAP Select e receber assistência do suporte técnico da NetApp. Um contrato de suporte vigente também é necessário para alterar parâmetros da licença, como capacidade ou tamanho do nó.
+
A compra de uma atualização de licença do Capacity Tier, alteração de parâmetros ou renovação de contrato de suporte exige o número de série do nó como parte do pedido. Os números de série dos nós do Capacity Tier têm nove dígitos e começam com o número '32'.

+
Após a conclusão da compra e a geração do arquivo de licença, ele é carregado no servidor Deploy usando a função *Update*.

* Uma *licença de Pool de Capacidade* é uma assinatura que dá direito ao uso de um pool específico de capacidade e tamanho de nó (padrão, premium, premium XL) para implantar um ou mais clusters. A assinatura inclui o direito de usar uma licença e suporte por um período determinado. O direito de usar a licença e o contrato de suporte têm datas de início e término específicas.


.Como o Deploy detecta se os nós têm licenças renovadas ou contrato de suporte?
A compra, geração e upload de um arquivo de licença atualizado é como o Deploy detecta licenças e contratos de suporte renovados.

Se a data de término de um contrato de suporte de Capacity Tier tiver expirado, o nó poderá continuar em execução, mas você não poderá baixar e instalar atualizações do ONTAP, nem entrar em contato com o suporte técnico da NetApp para obter assistência sem antes atualizar o contrato de suporte.

Se uma assinatura do Pool de Capacidade expirar, o sistema primeiro avisa, mas após 30 dias, se o sistema for desligado, ele não será reinicializado até que uma assinatura atualizada seja instalada no servidor de Deploy.



[[storage]]
== Storage

Existem diversas perguntas e respostas relacionadas ao armazenamento.

.Uma única instância do ONTAP Select Deploy pode criar clusters tanto em ESXi quanto em KVM?
Sim. ONTAP Select Deploy pode ser instalado tanto em KVM quanto em ESXi, e ambas as instalações podem criar clusters ONTAP Select em qualquer um dos hipervisores.

.O vCenter é necessário para o ONTAP Select no ESXi?
Se os hosts ESXi estiverem devidamente licenciados, então não há necessidade de os hosts ESXi serem gerenciados por um vCenter Server. No entanto, se os hosts forem gerenciados por um vCenter Server, então você deve configurar o ONTAP Select Deploy para usar esse vCenter Server. Em outras palavras, você não pode configurar hosts ESXi como independentes no ONTAP Select Deploy se eles estiverem sendo gerenciados ativamente por um vCenter Server. Observe que a VM do ONTAP Select Deploy depende do vCenter para rastrear todas as migrações de VMs do ONTAP Select entre hosts ESXi devido a um evento vMotion ou HA do VMware.

.O que é RAID por software?
ONTAP Select pode usar servidores sem um controlador RAID. Nesse caso, a funcionalidade RAID é implementada por software. Ao usar RAID por software, tanto unidades SSD quanto NVMe são suportadas. Os discos de inicialização e de despejo de memória do ONTAP Select ainda devem residir dentro de uma partição virtualizada (pool de storage ou datastore). ONTAP Select usa RD2 (particionamento root-data-data) para particionar os SSDs. Portanto, a partição de raiz do ONTAP Select reside nos mesmos discos físicos usados para os agregados de dados. No entanto, o agregado de raiz e os discos virtualizados de inicialização e de despejo de memória não são contabilizados na licença de capacidade.

Todos os métodos RAID disponíveis no AFF/FAS também estão disponíveis no ONTAP Select. Isso inclui RAID 4, RAID DP e RAID-TEC. O número mínimo de SSDs varia dependendo do tipo de configuração RAID escolhida. As melhores práticas exigem a presença de pelo menos um spare. Os discos de spare e paridade não são contabilizados na licença de capacidade.

.Como o RAID por software é diferente de uma configuração de RAID por hardware?
O RAID por software é uma camada na pilha de software do ONTAP. O RAID por software oferece mais controle administrativo porque os discos físicos são particionados e ficam disponíveis como discos brutos dentro da máquina virtual do ONTAP Select. Já com RAID por hardware, geralmente há um único LUN grande disponível que pode ser dividido para criar VMDISKs visíveis no ONTAP Select. O RAID por software está disponível como uma opção e pode ser usado em vez do RAID por hardware.

Alguns dos requisitos para RAID de software são os seguintes:

* Compatível com ESXi e KVM
+
** A partir do ONTAP Select 9.14.1, o suporte ao hipervisor KVM foi reintegrado. Anteriormente, o suporte ao hipervisor KVM havia sido removido no ONTAP Select 9.10.1.


* Tamanho dos discos físicos suportados: 200GB – 32TB
* Compatível apenas com configurações DAS
* Compatível com SSDs ou NVMe
* Requer uma licença Premium ou Premium XL do ONTAP Select
* O controlador RAID deve estar ausente ou desativado, ou deve operar no modo SAS HBA.
* Um pool de storage ou datastore baseado em um LUN dedicado deve ser usado para os discos do sistema: despejo de memória, boot/NVRAM e o Mediator.


.ONTAP Select para KVM suporta múltiplas agregações de NICs?
Ao instalar em KVM, você deve usar um único bond e uma única bridge. Um host com duas ou quatro portas físicas deve ter todas as portas no mesmo bond.

.Como o ONTAP Select reporta ou alerta sobre uma falha em um disco físico ou em uma NIC no host do hipervisor? O ONTAP Select obtém essas informações do hipervisor ou o monitoramento deve ser configurado no nível do hipervisor?
Ao usar um controlador RAID de hardware, ONTAP Select geralmente não tem conhecimento dos problemas subjacentes do servidor. Se o servidor estiver configurado de acordo com nossas melhores práticas, um certo nível de redundância deverá existir. Recomendamos RAID 5/6 para sobreviver a falhas de disco. Para configurações de RAID de software, ONTAP é responsável por emitir alertas sobre falha de disco e, se houver um disco sobressalente, iniciar a reconstrução do disco.

Você deve usar no mínimo duas NICs físicas para evitar um ponto único de falha na camada de rede. NetApp recomenda que os grupos de portas Data, Mgmt e Internal tenham o teaming e bonding de NICs configurados com dois ou mais uplinks no time ou bond. Essa configuração garante que, se houver alguma falha de uplink, o switch virtual mova o tráfego do uplink com falha para um uplink saudável no time de NICs. Para obter detalhes sobre a configuração de rede recomendada, consulte link:reference_plan_best_practices.html#networking["Resumo das melhores práticas: Networking"].

Todos os outros erros são tratados pelo ONTAP HA no caso de um cluster de dois ou quatro nós. Se o servidor hipervisor precisar ser substituído e o cluster ONTAP Select precisar ser reconstituído com um novo servidor, consulte _Posso recuperar um nó do ONTAP Select?_.

.Posso recuperar um nó ONTAP Select?
Contate o Suporte Técnico da NetApp se precisar recuperar um nó do ONTAP Select, por exemplo, se uma máquina virtual ONTAP Select ou host for completamente perdido ou se um cluster de nó único for excluído acidentalmente. Para obter mais informações, consulte o artigo da Knowledge Base link:https://kb.netapp.com/on-prem/ontap/ontap-select/Select-KBs/ONTAP_Select_node_VM_recovery_in_case_of_disaster["Recuperação da VM do nó ONTAP Select em caso de desastre"^].

.Qual é o tamanho máximo de datastore que o ONTAP Select suporta?
Todas as configurações, incluindo vSAN, suportam 400TB de armazenamento por nó ONTAP Select.

Ao instalar em datastores maiores que o tamanho máximo suportado, você deve usar o Capacity Cap durante a configuração do produto.

.Como posso aumentar a capacidade de um nó ONTAP Select?
ONTAP Select Deploy inclui um fluxo de trabalho de adição de storage que suporta a operação de expansão de capacidade em um nó ONTAP Select. Você pode expandir o storage sob gerenciamento usando espaço do mesmo datastore (se ainda houver espaço disponível) ou adicionar espaço de um datastore separado. A combinação de datastores locais e remotos no mesmo agregado não é suportada.

A adição de armazenamento também suporta RAID por software. No entanto, no caso de RAID por software, unidades físicas adicionais devem ser adicionadas à máquina virtual ONTAP Select. A adição de armazenamento, nesse caso, é semelhante ao gerenciamento de um array FAS ou AFF. Os tamanhos dos grupos RAID e dos discos devem ser considerados ao adicionar armazenamento a um nó ONTAP Select usando RAID por software.

.ONTAP Select oferece suporte a vSAN ou datastores do tipo array externo?
ONTAP Select Deploy e ONTAP Select para ESXi suportam a configuração de um cluster de nó único ONTAP Select usando um datastore do tipo vSAN ou array externo para seu pool de storage.

O ONTAP Select Deploy e o ONTAP Select for KVM oferecem suporte à configuração de um cluster de nó único do ONTAP Select usando um tipo de pool de storage lógico compartilhado em arrays externos. Os pools de storage podem ser baseados em iSCSI ou FC/FCoE. Outros tipos de pool de storage não são suportados.

É possível configurar clusters HA com múltiplos nós em storage compartilhado.

.O ONTAP Select oferece suporte a clusters com vários nós em vSAN ou outro storage externo compartilhado, incluindo alguns stacks HCI?
Clusters com múltiplos nós usando storage externo (vNAS com múltiplos nós) são suportados tanto para ESXi quanto para KVM. A combinação de hipervisores no mesmo cluster não é suportada. Uma arquitetura de HA em storage compartilhado ainda implica que cada nó em um par de HA tenha uma cópia espelhada dos dados do parceiro. No entanto, um cluster com múltiplos nós traz os benefícios das operações não disruptivas do ONTAP, em oposição a um cluster de nó único que depende do VMware HA ou do KVM Live Motion.

Embora o ONTAP Select Deploy adicione suporte para várias ONTAP Select VMs no mesmo host, ele não permite que essas instâncias façam parte do mesmo cluster ONTAP Select durante a criação do cluster. Para ambientes ESXi, a NetApp recomenda criar regras de antiafinidade de VM para que o VMware HA não tente migrar várias ONTAP Select VMs do mesmo cluster ONTAP Select para um único host ESXi. Além disso, se o ONTAP Select Deploy detectar que uma vMotion administrativa (iniciada pelo usuário) ou migração ao vivo de uma ONTAP Select VM resultou em uma violação da nossa melhor prática, como dois nós ONTAP Select acabarem no mesmo host físico, o ONTAP Select Deploy exibirá um alerta na interface do Deploy e no log. A única maneira de o ONTAP Select Deploy tomar conhecimento da localização da ONTAP Select VM é como resultado de uma operação de atualização do cluster, que é uma operação manual que o administrador do ONTAP Select Deploy deve iniciar. Não há funcionalidade no ONTAP Select Deploy que permita o monitoramento proativo, e o alerta só é visível pela interface do Deploy ou pelo log. Em outras palavras, esse alerta não pode ser encaminhado para uma infraestrutura de monitoramento centralizada.

.O ONTAP Select é compatível com o VXLAN do NSX da VMware?
Os grupos de portas VXLAN do NSX-V são compatíveis. Para HA com vários nós, incluindo ONTAP MetroCluster SDS, certifique-se de configurar o MTU da rede interna entre 7500 e 8900 (em vez de 9000) para acomodar a sobrecarga do VXLAN. A MTU da rede interna pode ser configurada com o ONTAP Select Deploy durante a implantação do cluster.

.ONTAP Select suporta migração ao vivo de KVM?
As VMs ONTAP Select que são executadas em pools de armazenamento de arrays externos suportam migrações ao vivo do virsh.

.Preciso do ONTAP Select Premium para o vSAN AF?
Não, todas as versões são suportadas independentemente de as configurações do array externo ou do vSAN serem all flash.

.Quais configurações de vSAN FTT/FTM são suportadas?
A VM Select herda a política de armazenamento do datastore vSAN e não há restrições nas configurações de FTT/FTM. No entanto, observe que, dependendo das configurações de FTT/FTM, o tamanho da VM ONTAP Select pode ser significativamente maior do que a capacidade configurada durante sua configuração. ONTAP Select usa VMDKs thick-eager, zeroed que são criados durante a configuração. Para evitar afetar outras VMs que usam o mesmo datastore compartilhado, é importante fornecer capacidade livre suficiente no datastore para acomodar o tamanho real da VM Select, conforme derivado da capacidade Select e das configurações de FTT/FTM.

.Vários nós do ONTAP Select podem ser executados no mesmo host se fizerem parte de clusters Select diferentes?
É possível configurar vários nós ONTAP Select no mesmo host apenas para configurações vNAS, desde que esses nós não façam parte do mesmo cluster ONTAP Select. Isso não é compatível com configurações DAS, pois vários nós ONTAP Select no mesmo host físico competiriam pelo acesso ao controlador RAID.

.É possível ter um host com uma única porta 10GE executando ONTAP Select, e ele está disponível tanto para ESXi quanto para KVM?
Você pode usar uma única porta 10GE para se conectar à rede externa. No entanto, a NetApp recomenda que você use isso apenas em ambientes pequenos com restrições de formato. Isso é compatível tanto com ESXi quanto com KVM.

.Quais processos adicionais você precisa executar para realizar uma migração ao vivo no KVM?
Você deve instalar e executar os componentes de código aberto CLVM e pacemaker (pcs) em cada host participante da migração dinâmica. Isso é necessário para acessar os mesmos grupos de volumes em cada host.



[[vcenter]]
== vCenter

Existem diversas perguntas e respostas relacionadas ao VMware vCenter.

.Como o ONTAP Select Deploy se comunica com o vCenter e quais portas de firewall devem ser abertas?
ONTAP Select Deploy utiliza a API VIX da VMware para se comunicar com o vCenter, host ESXi ou ambos. A documentação da VMware indica que a conexão inicial com um vCenter Server ou um host ESXi é feita usando HTTPS/SOAP na porta TCP 443. Esta é a porta para HTTP seguro sobre TLS/SSL. Em seguida, uma conexão com o host ESXi é aberta em um socket na porta TCP 902. Os dados transmitidos por esta conexão são criptografados com SSL. Além disso, ONTAP Select Deploy emite um `PING` comando para verificar se há um host ESXi respondendo no endereço IP especificado.

ONTAP Select Deploy também deve ser capaz de se comunicar com os endereços IP de gerenciamento do nó e do cluster do ONTAP Select da seguinte forma:

* Ping
* SSH (porta 22)
* SSL (porta 443)


Para clusters de dois nós, ONTAP Select Deploy hospeda as caixas de correio do cluster. Cada nó do ONTAP Select deve ser capaz de alcançar o ONTAP Select Deploy por meio de iSCSI (porta 3260).

Para clusters com vários nós, a rede interna deve estar totalmente aberta (sem NAT ou firewalls).

.Quais direitos do vCenter o ONTAP Select Deploy precisa para criar clusters ONTAP Select?
A lista de direitos do vCenter necessários está disponível aqui: link:reference_plan_ots_vcenter.html["Servidor VMware vCenter"].



[[ha-and-clusters]]
== HA e clusters

Existem diversas perguntas e respostas relacionadas a pares de HA e clusters.

.Qual a diferença entre um cluster de quatro, seis ou oito nós e um cluster de dois nós ONTAP Select?
Ao contrário dos clusters de quatro, seis e oito nós, nos quais a VM ONTAP Select Deploy é usada principalmente para criar o cluster, um cluster de dois nós depende continuamente da VM ONTAP Select Deploy para o quorum de HA. Se a VM ONTAP Select Deploy estiver indisponível, os serviços de failover são desativados.

.O que é MetroCluster SDS?
MetroCluster SDS é uma opção de replicação síncrona de baixo custo que se enquadra na categoria das soluções de Continuidade de Negócios MetroCluster da NetApp. Está disponível apenas com ONTAP Select, diferentemente do NetApp MetroCluster, que está disponível no FAS Hybrid Flash, AFF e NetApp Private Storage for Cloud.

.Como a MetroCluster SDS é diferente da NetApp MetroCluster?
MetroCluster SDS oferece uma solução de replicação síncrona e se enquadra nas soluções NetApp MetroCluster. No entanto, uma diferença fundamental é o tipo de conectividade (apenas redes IP são suportadas em vez de FC e IP).

.Qual a diferença entre um cluster de dois nós ONTAP Select e um ONTAP MetroCluster SDS de dois nós?
Um cluster de dois nós é definido como um cluster em que ambos os nós estão no mesmo data center, a uma distância máxima de 300m um do outro. Em geral, ambos os nós possuem uplinks para o mesmo switch de rede ou conjunto de switches de rede conectados por um Inter-Switch Link.

O MetroCluster SDS de dois nós é definido como um cluster com nós fisicamente separados (salas diferentes, edifícios diferentes ou centros de dados diferentes) e as conexões de uplink de cada nó são conectadas a switches de rede separados. Embora MetroCluster SDS não exija hardware dedicado, o ambiente deve suportar os requisitos mínimos de latência (5 ms RTT e 5 ms jitter, totalizando um máximo de 10 ms).

MetroCluster SDS é um recurso premium e requer a licença Premium ou Premium XL. Uma licença Premium permite a criação de VMs de pequeno e médio porte, bem como mídias HDD e SSD. Todas essas configurações são suportadas.

.O ONTAP MetroCluster SDS requer armazenamento local (DAS)?
ONTAP MetroCluster SDS suporta todos os tipos de configurações de armazenamento (DAS e vNAS).

.O ONTAP MetroCluster SDS oferece suporte a RAID por software?
Sim, RAID por software é compatível com mídias SSD tanto em KVM quanto em ESXi.

.O ONTAP MetroCluster SDS é compatível tanto com SSDs quanto com mídias rígidas?
Sim, embora seja necessária uma licença Premium, essa licença é compatível com VMs de pequeno e médio porte, bem como com SSDs e mídias rígidas.

.O ONTAP MetroCluster SDS oferece suporte a clusters com quatro nós ou mais?
Não, apenas clusters de dois nós com um Mediator podem ser configurados como MetroCluster SDS.

.Quais são os requisitos para ONTAP MetroCluster SDS?
Os requisitos são os seguintes:

* Três centros de dados (um para o ONTAP Select Deploy Mediator e um para cada nó)
* RTT de 5 ms e jitter de 5 ms para um total máximo de 10 ms
* RTT de 125 ms e largura de banda mínima de 5 Mbps entre o ONTAP Select Deploy Mediator e cada nó do ONTAP Select
* Uma licença Premium ou Premium XL


.O ONTAP Select é compatível com vMotion ou VMware HA?
ONTAP Select VMs executadas em datastores vSAN ou datastores de array externos (ou seja, implementações vNAS) oferecem suporte a vMotion, DRS e funcionalidades VMware HA.

.O ONTAP Select oferece suporte ao Storage vMotion?
Storage vMotion é compatível com todas as configurações, incluindo cluster de nó único e de vários nós do ONTAP Select e a VM ONTAP Select Deploy. Storage vMotion pode ser usado para migrar o ONTAP Select ou a VM ONTAP Select Deploy entre diferentes versões do VMFS (por exemplo, de VMFS 5 para VMFS 6), mas não está restrito a esse caso de uso. A melhor prática é desligar a VM antes de iniciar uma operação de Storage vMotion. ONTAP Select Deploy deve executar a seguinte operação após a conclusão da operação de storage vMotion:

[listing]
----
cluster refresh
----

NOTE: Uma operação de storage vMotion entre diferentes tipos de datastores não é suportada. Em outras palavras, operações de storage vMotion entre datastores do tipo NFS e datastores VMFS não são suportadas. De forma geral, operações de storage vMotion entre datastores externos e datastores DAS não são suportadas.

.O tráfego de interconexão HA entre nós ONTAP Select pode ser executado em um vSwitch diferente e/ou em portas físicas segregadas e/ou usando cabos IP ponto a ponto entre hosts ESXi?
Essas configurações não são suportadas. ONTAP Select não tem visibilidade do status dos uplinks de rede física que transportam o tráfego do cliente. Portanto, ONTAP Select depende do heartbeat de HA para garantir que a VM esteja acessível aos clientes e ao seu par simultaneamente. Quando ocorre uma perda de conectividade física, a perda do heartbeat de HA resulta em um failover automático para o outro nó, que é o comportamento desejado.

A segregação do tráfego de HA em uma infraestrutura física separada pode resultar em uma VM Select conseguindo se comunicar com seu par, mas não com seus clientes. Isso impede o processo automático de HA e resulta na indisponibilidade de dados até que uma falha manual seja acionada.



[[mediator-service]]
== Serviço de mediação

Existem diversas perguntas e respostas relacionadas ao serviço de mediação.

.O que é o serviço Mediator?
Um cluster de dois nós depende continuamente da VM ONTAP Select Deploy para o quorum de HA. Uma VM ONTAP Select Deploy que participa de uma negociação de quorum de HA de dois nós é denominada Mediator VM.

.O serviço Mediator pode ser remoto?
Sim. ONTAP Select Deploy atuando como mediador para um par de HA de cluster de dois nós suporta uma latência de WAN de até 500ms RTT e requer uma largura de banda mínima de 5Mbps.

.Qual protocolo o serviço Mediator utiliza?
O tráfego do Mediator é iSCSI, origina-se nos endereços IP de gerenciamento do nó ONTAP Select e termina no endereço IP do ONTAP Select Deploy. Observe que não é possível usar IPv6 para o endereço IP de gerenciamento do nó ONTAP Select ao usar um cluster de dois nós.

.Posso usar um único serviço Mediator para vários clusters de dois nós de HA?
Sim. Cada VM do ONTAP Select Deploy pode servir como um serviço Mediator comum para até 100 clusters ONTAP Select de dois nós.

.É possível alterar a localização do serviço Mediator após a implantação?
Sim. É possível usar outra VM do ONTAP Select Deploy para hospedar o serviço Mediator.

.ONTAP Select suporta clusters estendidos com (ou sem) o Mediator?
Apenas um cluster de dois nós com um Mediator é suportado em um modelo de implantação de par de HA estendida.
